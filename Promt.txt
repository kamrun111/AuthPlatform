CLEAN ARCHITECTURE REQUIREMENTS:
- Clean Architecture is the top priority.
- No classic UnitOfWork pattern.
- EF Core for write operations.
- Dapper for read and write operations.
- Domain = entities + interfaces + rules.
- Application = services (use cases), DTOs, validators.
- Infrastructure = EF Core, Dapper, repositories, hashing, JWT.
- API = controllers + middleware.
- MVC = client app calling API only (never touches database).

AUTH & PERMISSION REQUIREMENTS:
- Custom authentication module using the following entities:
    - AuthUser
    - AuthRole
    - AuthPermission
    - AuthUserPermission
    - AuthRolePermission
    - AuthLoginHistory
    - AuthAuditActivity
- Permissions must support:
    - Role-based (group)
    - User-based (individual)
- JWT Authentication + Refresh Tokens
- Secure password hashing (PBKDF2 or BCrypt)
- Claims-based + permission-based authorization
- API must remain stateless

TOKEN STORAGE:
- MVC must NOT store JWT in browser storage.
- MVC stores Access + Refresh tokens in server-side session.
- Browser only holds a Secure, HttpOnly session cookie.
- MVC attaches Access Token as Bearer token when calling API.

RDLC REPORTING REQUIREMENTS:
- RDLC will be used as the reporting tool (free, no license).
- Two types of reports:
    1. Reports WITHOUT parameters (e.g., Active Users, Dashboard Summary)
    2. Reports WITH parameters (e.g., User Permission, Role Permission, Login History, Audit Activity)
- RDLC reports must be generated server-side in MVC.
- Data for reports must come from Dapper.
- Export formats: PDF, Excel.
